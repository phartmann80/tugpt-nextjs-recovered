### Expect the FX nag

Preflight will warn that the ECB rate is stale: the seeded rate is
**1 EUR = 1.1578 USD, reference date 2026-09-02**. That is a warning, not a
blocker, by design (#72) — the rate and its date are stored on every converted
row, so staleness can only move an enforcement decision and can never corrupt
what was recorded.

## 5. New standing item: monthly ECB rate refresh

### Eight applied, not the nine this sheet predicted

The sheet predicted nine and told the operator to stop on anything else. Eight
were applied and the deploy was correct. **The prediction was wrong, not the
deploy** — worth recording, because a stop-rule that cries wolf gets ignored.

The nine were derived from an assumed server baseline of `20260902000002`
(contact entity). §2 flagged that baseline as unverified, and it was off by
one: `20260903000001_plans_and_entitlements` was **already applied** to the
server before this deploy. So the true baseline was **46 migrations**, and
54 − 46 = **8**. The arithmetic reconciles exactly.

The applied set was therefore everything strictly after
`20260903000001_plans_and_entitlements`:

```
20260903000002_provider_usage_and_cost.sql          <- #68, merged 09-03, never deployed
20260903000003_secret_storage.sql
20260903000004_voice_transcription_flag_and_gladia_price.sql
20260903000005_multi_currency_and_langdock_prices.sql
20260903000006_fx_conversion.sql
20260903000007_fx_status_rpc.sql
20260903000008_transcript_ingest.sql
20260904000001_revoke_destructive_table_grants.sql
```

**Lesson for the next sheet:** derive the expected count from the database's
actual `supabase_migrations.schema_migrations` state, not from merge history.
The reliable gate was never the count — it was the preflight line
`all 54 migration(s) ... latest 20260904000001`, which is an assertion about
the end state rather than about a delta. Prefer that as the stop-rule.
